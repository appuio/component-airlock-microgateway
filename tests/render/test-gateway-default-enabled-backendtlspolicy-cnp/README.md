# Render-test scenarios

Offline golden-file tests for the `backendtlspolicy-cnp` ManagedResource. Each case here is a directory `<case>/input.yaml` containing a single YAML
document shaped like a real cluster snapshot, with its golden at
`<case>/output.yaml`:

```
triggers:
  - {}          # ONE entry per input: the CLI renders one output document per
                # trigger, so two entries duplicate the render
context:
  - name: services
    resources: [...]
  - name: backendtlspolicies
    resources: [...]
  - name: ciliumnetworkpolicies
    resources: [...]
libraries: {}
```

The suite is run by `make test-espejote` (or
`make test-espejote-one -e MR=test-gateway-default-enabled-backendtlspolicy-cnp`),
which invokes this suite's `run.sh` with the dockerized `ESPEJOTE_CMD`; drift
from the committed goldens fails the script directly. Regenerate goldens with
`make gen-espejote` or
`bash tests/render/test-gateway-default-enabled-backendtlspolicy-cnp/run.sh --update`.

## Offline caveat (label pre-filtering)

In a real cluster, the `ciliumnetworkpolicies` context is filled by the
server-side labelSelector of the ManagedResource:

```yaml
labelSelector:
  matchLabels:
    espejote.io/managed-resource: backendtlspolicy-cnp
```

Offline, espejote does NOT re-apply that selector. Every CNP placed in a
scenario's `ciliumnetworkpolicies` array therefore already carries the
`espejote.io/managed-resource: backendtlspolicy-cnp` label, exactly as the
cluster would have delivered it — that is what makes it sweep-visible.
Offline, espejote also does not re-apply the context's `namespace:` scoping,
so CNP context objects must carry `namespace: test-gateway-default-enabled` themselves.

## Scenario intents

Each input file documents its scenario and expected render in a top-of-file
comment; each case's `output.yaml` is the committed outcome.

## Observed CLI behavior (verified against espejote v0.22.0 offline renders)

- Each input carries a single `- {}` trigger — the CLI renders one output
  document per trigger, so two entries would duplicate the render.
- `esp.markForDelete` renders the whole context object plus a top-level key
  `__internal_use_espejote_lib_deletion: {delete: true}`.
- Nulls from `cnpFor` appear verbatim as `- null` list items in the render
  output (they are skipped when building `desiredNames`, which is what makes
  them harmless).
- Rendered CNPs carry `namespace: test-gateway-default-enabled` (substituted at compile time from the instance key) and are
  key-alphabetized (JSON round-trip by the CLI); goldens are generated by
  running the harness, not hand-written.
- The `empty.yaml` golden is `---` + `[]`.
